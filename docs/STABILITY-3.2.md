# 3.2.0-stability-test1 稳定性修复说明

本版基于 3.1.0-key-test1，保留低档扬声器曲线、全局 0–100、原生面板内的分应用滑块和长按加速。适用设备、ROM 哈希及 LSPosed 作用域不变。新版尚未在平板上实测，作为预发布版本提供。

## 问题、方案与验收

| 已确认的软件问题 | 本版处理 | 验证方法 |
| --- | --- | --- |
| 有保存规则但没有播放时，后台仍每 50ms 获取完整播放配置 | 活跃或持有效果对象时约 100ms；有规则但空闲时约 1000ms；无规则或禁用时约 2000ms，且不查询播放配置 | 主机测试验证节奏、无规则时不调用 AudioService，以及首次设置能唤醒空闲后台 |
| 降低检查频率可能增加手动修改延迟 | Native socket 保存成功后通知同进程后台；代数计数避免通知早于 wait 时丢失 | 空闲后设置、通知先于 wait、现有音效原地更新测试 |
| 内层捕获音效错误，导致创建、参数更新或释放失败后不断重试 | 每 session 按 1/2/4/8/16/30 秒退避，最长 30 秒；拖动不绕过退避；成功或会话结束清理重试记录 | 故障注入验证每个边界、保留错误状态及恢复；其他健康 session 继续运行 |
| 暂停/停止配置仍存在时，不断续期音效资源 | 暂停从最近一次播放检查起保留最多约 5 秒，停止/释放立即申请释放；缺失快照仍保留原有 1.2 秒宽限 | 暂停到期、恢复重建、明确停止、短快照缺口测试 |
| 释放失败后可能对复用 session 的新 UID 使用旧句柄 | 旧所有者未成功释放时，阻止新 UID 更新该句柄；释放成功再创建 | 两个 UID 复用 session，注入释放失败并验证独立 session 可继续调节 |
| SystemUI 客户端即使界面隐藏也每 40ms 运行定时任务 | 构造时不调度；显示或有待提交值时才启动；隐藏后排空已提交修改，再关闭 socket 并取消任务 | 隐藏、重新展开、立即关闭后的末值提交、迟到 ACK 测试 |
| 状态相同仍每 2 秒替换状态文件 | 状态变化立即写，稳定状态约 30 秒心跳；诊断新鲜度阈值同步改为 90 秒 | 无规则空闲超过旧心跳周期后，验证文件时间不变 |
| 外层后端错误连续快速重试 | 同样按秒退避，连续 10 次失败后退出；恢复时尝试释放全部句柄，避免一个失败阻止其余释放 | 代码审查；Android 后端故障仍需设备验证 |

以上是代码调度周期，不代表实测 CPU、温度、电池或延迟数值。进程调度和 Binder 调用可能延长实际间隔。跨进程 CLI、Magisk 停用文件及外部规则修改通过下一轮检查发现；普通音量面板的 SET 使用即时通知路径。

## 取舍与已知限制

- 新播放开始时，保存的衰减规则可能在下一次空闲检查时才附加，通常检查周期约 1 秒；本实现不能保证第一帧音频已衰减。修复这一点需要在音频创建路径上拦截，属于更高风险的另一项改动。
- 暂停超过宽限期后会释放效果，恢复播放时需要重新附加；仍应以较低系统音量测试首音及音量突变。
- 参数/控制异常时，已成功建立的音效尽量保留，不为重试主动恢复全音量。但失去控制权或音频服务重启时，不能保证衰减持续有效。
- 释放本身失败时，只能记录并退避重试，不能承诺底层资源立刻释放。SessionEngine 不把失败释放的旧句柄交给新 UID。
- 活跃音效仍约每秒重设并读回增益，用于发现失控或禁用。原生 UI 展开时仍有列表更新，关闭后停止 UI 定时任务，音频后台独立运行。
- 没有增加 wakelock、性能模式、CPU/电压/温控设置、充电参数或分区写入，也没有新增长驻重启看门狗。

## 设备验证计划

1. 配套覆盖安装新版 ZIP 与 APK，保留 SystemUI 和 Android 两个作用域后重启；签名沿用原密钥。
2. 低系统音量下，让两个应用同时播放，分别调至 30%/70%，重复拖动到 100%，确认互不影响、没有短暂突增。
3. 关闭面板并熄屏，确认后台播放持续；重新打开面板检查保存值。
4. 暂停短于 5 秒、暂停超过 5 秒、停止后重播，分别验证恢复的音量及首音。
5. 保存规则后停止全部播放，观察空闲；之后播放音乐并调节应用滑块，检查响应。
6. 检查 LSPosed 与 Magisk Action 日志有无重复错误；比较相同播放、亮度、网络条件下的 CPU/温度记录。主机测试不能替代这一项。
7. 若不稳定，停用本版并恢复配套的 3.1.0 ZIP/APK；若 Android 不允许降低 APK 版本号，先在 LSPosed 停用模块，再卸载新版 APK 后安装旧版，重启。音量规则保存在 Magisk 数据目录；不要为回退删除整个数据目录。

## 关于此前无法开机的故障

此前审核未发现直接修改硬件性能或热管理的代码，但轮询和重试问题确实值得修复。没有故障前的温度、电流、系统崩溃或硬件检测数据，无法判断模块是否间接参与故障，也不能据此排除其他系统问题。软件静态审查与主机测试不能诊断 CPU 焊点，不能把本版视为硬件故障修复或预防措施。
